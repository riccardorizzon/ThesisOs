# ADR-0011: Streaming-First LLM Interface

- Status: Accepted (frozen 2026-06-24)
- Context: M1 introduces a real conversational loop whose value depends on token-by-token streaming (Vertex → SSE → React renders `assistant += token`). The frozen M0 `LLMClient` Protocol exposes only `generate(messages) -> str`, which returns a fully-formed string and therefore cannot stream. Keeping only `generate()` would force a later rewrite of `/chat`, `ConversationService`, the LangGraph node, and the frontend once streaming is needed — the exact contract churn ADR-0001 exists to prevent. At the same time, ADR-0002 requires the provider to stay hidden behind a LiteLLM seam, and existing callers/tests rely on the current synchronous methods.
- Decision: Extend the `LLMClient` Protocol **additively**. Keep `generate()`, `embed()`, and `vision()` byte-for-byte unchanged (same `list[dict]` message convention, same return types). Add `astream(messages, *, model=None, params=None) -> AsyncIterator[TokenChunk]` as the streaming entry point, and define the value type `TokenChunk` now even though M1 consumes only `text`. `TokenChunk` is **frozen to exactly three fields** — `text: str` (required), `finish_reason: str | None = None`, `metadata: dict = {}` — and no further fields may be added in M1. The `conversation_node` consumes the LLM via `async for chunk in llm.astream(...)`. A synchronous `stream()` is optional and not required. No existing method signature changes; no breaking change.
- Consequences: M1 gets real streaming without disturbing frozen contracts; old code calling `await llm.generate()` keeps working while new code uses `astream()`. The `TokenChunk` envelope is stable, so future milestones (M5 retrieval, M7 citation, M12 multi-agent) can enrich `metadata`/`finish_reason` without another signature change, and the Conversation Node keeps producing a stream regardless of how many nodes surround it. The cost is two ways to call the LLM (full vs streamed), accepted as the deliberate streaming-first seam. `NotConfiguredLLM` also implements `astream` (raising the same not-configured error) so the Protocol stays total.
- Alternatives considered: (a) Replace `generate() -> str` with a streaming signature — rejected as a breaking change to a frozen contract. (b) Stream only via LangGraph-native token streaming using a LangChain chat model (`ChatLiteLLM`/`ChatVertexAI`) inside the node — rejected because it dissolves the hand-owned LiteLLM seam into framework magic and couples streaming to LangGraph internals. (c) Keep the Protocol literally unchanged and put streaming in a separate free function outside the Protocol — rejected because it splits the LLM surface into two inconsistent call paths with no shared contract.
